1 Vue d'ensemble de l'application

Oryalis est un CRM SaaS mobile-first destiné aux praticiens du bien-être (naturopathes, thérapeutes, conseillers doTERRA…). Il permet de gérer les clients, les rendez-vous, les relances, les notes de séance et les recommandations de produits, le tout synchronisé en temps réel avec Supabase.

2 Base de données Supabase

La base de données est hébergée sur Supabase (PostgreSQL 15, région eu-west-1). Toutes les tables ont la Row Level Security (RLS) activée : un utilisateur ne peut voir et modifier que ses propres données.

Instance Supabase : nhpvjfyjyculnijipzoa
Migrations : scripts Node.js migrate*.mjs (jamais le CLI Supabase — projet sur compte tiers)

Row Level Security (RLS)

Chaque table a RLS activé. Les politiques garantissent qu'un praticien ne peut accéder qu'à ses propres données.

-- Politique standard (clients, appointments, notes, followups, recommendations) CREATE POLICY "user_own_rows" ON table_name USING (auth.uid() = user_id) WITH CHECK (auth.uid() = user_id); -- Exception : catalogues officiels (visibles par tous) CREATE POLICY "official_catalogs_visible" ON catalogs USING (user_id IS NULL AND type = 'official'); -- Exception : catalog_products des catalogues officiels CREATE POLICY "official_products_visible" ON catalog_products USING ( EXISTS ( SELECT 1 FROM catalogs WHERE id = catalog_id AND (user_id IS NULL OR user_id = auth.uid()) ) );

3 Synchronisation Calendrier

La synchronisation calendrier (expo-calendar ~56.0.8) crée un calendrier dédié "Oryalis" sur l'appareil iOS ou Android du praticien et y pousse les rendez-vous Supabase. Elle affiche aussi les événements personnels de l'utilisateur dans la vue agenda, avec une distinction visuelle claire.

Web : toutes les fonctions calendrier sont désactivées silencieusement sur Platform.OS === 'web'. Le module expo-calendar n'est jamais importé au niveau module (import conditionnel / require() lazy dans chaque fonction).

Architecture des fichiers

FichierRôle
features/appointments/calendarSyncService.tsService pur : accès à expo-calendar, pas de hooks React. Toutes les opérations natives.
features/appointments/useCalendarSync.tsHook React : orchestre le service, gère l'état (syncing, error), accès Supabase pour sauvegarder native_event_id.
app/(app)/settings.tsxSection "Calendrier" : bouton sync, message d'erreur inline.
app/(app)/appointments/index.tsxVue agenda : affiche les événements personnels (non-Oryalis) en superposition.

Flux de synchronisation — Push vers le calendrier natif

1
Demande de permission
Calendar.requestCalendarPermissionsAsync() — demande l'accès au calendrier natif. Si status !== 'granted', la fonction retourne null et le hook expose error = 'calendar_permission_denied'. Le message d'erreur s'affiche inline dans les Réglages.
2
Création / récupération du calendrier "Oryalis"
getOrCreateOryalisCalendar() cherche d'abord un calendrier existant nommé "Oryalis" dans la liste des calendriers natifs.
• S'il existe → retourne son id
• Sinon → le crée avec la couleur #6D3BFF (violet Oryalis)
  • iOS : récupère la source LOCAL ou CALDAV
  • Android : crée avec ownerAccount: 'personal' et CalendarAccessLevel.OWNER
3
Récupération des RDV Supabase
syncAllToNative() charge tous les appointments du praticien depuis Supabase avec la colonne native_event_id et le nom du client (join clients).
4
Création ou mise à jour de l'événement natif
pushAppointmentToCalendar(calendarId, appt) pour chaque RDV :
• Si native_event_id existe → Calendar.updateEventAsync()
• Si native_event_id est null → Calendar.createEventAsync()

Format de l'événement créé :
— Titre : 🟣 {Nom client} — RDV #{numéro}
— Durée : 60 minutes (valeur par défaut)
— Notes : [Oryalis] {thèmes abordés}
5
Sauvegarde du native_event_id en base
Si un nouvel événement a été créé (pas de native_event_id avant), l'ID retourné par expo-calendar est sauvegardé dans appointments.native_event_id via Supabase. Cela permet les mises à jour futures sans créer de doublons.

Fonctions exposées par le service

FonctionSignatureDescription
getOrCreateOryalisCalendar () → Promise<string | null> Retourne l'id du calendrier "Oryalis" (crée si absent). Null sur web ou si permission refusée.
pushAppointmentToCalendar (calId, appt) → Promise<string | null> Crée ou met à jour un événement natif. Retourne le native_event_id.
deleteAppointmentFromCalendar (nativeEventId) → Promise<void> Supprime l'événement natif. À appeler avant la suppression en base.
fetchAllNativeEvents (from, to) → Promise<NativeCalendarEvent[]> Lit TOUS les calendriers natifs (Oryalis + personnels) sur la période. Retourne le flag isOryalis.

Type NativeCalendarEvent

type NativeCalendarEvent = { id: string // ID natif de l'événement title: string // Titre de l'événement startDate: string // ISO string endDate: string // ISO string notes?: string calendarId: string // ID du calendrier source calendarTitle: string // Nom du calendrier (ex: "Oryalis", "iPhone") calendarColor: string // Couleur hex native du calendrier isOryalis: boolean // true si calendarTitle === 'Oryalis' }

Affichage dans la vue agenda

Les événements natifs personnels (non-Oryalis) sont affichés en superposition sur la grille horaire, à côté des RDV Supabase du praticien.

Type d'événementStyle visuelSource
🟣 RDV Oryalis Palette de couleurs cyclique par client (violet, bleu, vert…), barre colorée à gauche Supabase appointments
👤 Événement personnel Fond colors.bgDim (discret), barre gauche = couleur native du calendrier, badge "Personnel", opacity 0.9 Calendrier natif iOS/Android (isOryalis = false)
Anti-duplication : les événements Oryalis synchonisés vers le calendrier natif (isOryalis = true) sont filtrés de l'affichage natif — ils sont déjà affichés via les données Supabase. Seuls les événements isOryalis = false sont superposés.
